# 项目级 AI 开发规则

## 一、项目定位

本项目以 `SpringAi-MCP-RAG-Dev` 为基础，是一个独立开发、独立运行的 AI 应用。项目通过直接连接外部 CRM MySQL 测试数据库，读取经过授权的 CRM 业务数据，为企业管理者提供自然语言业务查询和分析能力。

**本项目不是 CRM 系统内部模块，不在 CRM 源码项目中开发，也不应擅自修改 CRM 代码、表结构、触发器或其他数据库对象。**

CRM 是外部业务数据源；`SpringAi-MCP-RAG-Dev` 是本项目的开发主体。除非得到明确授权，本项目只对 CRM 数据库执行只读操作。

## 二、项目目标

1. 在现有 `SpringAi-MCP-RAG-Dev` 技术架构上扩展 CRM 数据分析能力。
2. 通过自然语言理解用户的业务问题。
3. 通过 Spring AI / Tool Calling 调用受控的 Java 业务工具。
4. 使用经过验证的 SQL 和 Java 业务逻辑查询、计算 CRM 数据。
5. 让模型基于真实工具结果组织自然语言回答。
6. 确保查询准确、权限明确、数据安全、实现可测试且可维护。

## 三、开发前必须检查

- 阅读 `docs/ai-agent/PROJECT_CONTEXT.md`。
- 阅读 `docs/ai-agent/DATABASE_SCHEMA.md`。
- 阅读 `docs/ai-agent/BUSINESS_METRICS.md`。
- 阅读 `docs/ai-agent/DEVELOPMENT_LOG.md`。
- 阅读 `.qoder/rules/crm-data-agent.md`。
- 检查当前仓库的模块结构、依赖版本、配置方式、已有模型调用、MCP、RAG、Tool Calling、数据访问和异常处理实现。
- 优先复用当前仓库的现有能力，不要假设项目结构与其他项目相同。
- 不要在未检查代码前直接创建重复的框架或大规模重构。

## 四、数据库连接和环境边界

- CRM MySQL 是外部数据源，本项目独立配置连接信息。
- 当前已知有测试数据库，应优先使用测试环境验证。
- 数据库地址、用户名、密码必须通过项目现有安全配置机制或环境变量提供。
- 不得将真实凭证提交到 Git、写入文档、提示词、日志或示例代码。
- 优先申请最小权限的只读数据库账号。
- 不得执行 `INSERT`、`UPDATE`、`DELETE`、`DROP`、`ALTER`、`TRUNCATE` 等写入或结构变更操作，除非用户明确授权且已确认操作环境与影响。
- 未确认数据库连接配置前，不得自行尝试连接任何数据库。
- 不要把 CRM 数据复制到本项目的新表或其他存储中，除非需求明确要求并完成安全评估。

## 五、业务规则不能靠猜

以下规则必须依据产品经理、业务负责人确认的口径或现有系统中已验证的实现：

- 有效订单状态和退单、退款、部分退款的处理方式。
- 实收金额、零售金额、营业额、毛利的定义。
- 消费次数是订单数、交易笔数还是会员消费频次。
- 线上、线下、平台、门店和租户的统计范围。
- 会员新增、活跃、复购等指标的定义。
- 默认时间范围和时间边界。
- 删除标记的实际含义。
- 会员累计字段的计算周期和更新机制。

如果规则不明确，列出待确认问题，不得把推测当作事实。

## 六、SQL 和数据访问安全

- 不允许把用户自然语言直接拼接成 SQL。
- 不允许让大模型自由生成 SQL 后未经校验直接执行。
- 优先采用经过审核的 SQL 模板、Mapper 或受控查询服务。
- 所有参数都必须在服务端校验。
- 对日期跨度、返回行数、分页、查询耗时和可查询字段设置合理限制。
- 数据权限必须由服务端执行，不得由大模型自行决定。
- 在订单表与明细表联查时，先明确一对多关系，避免订单级金额重复累计。
- 金额和数量字段若为 VARCHAR，必须验证格式、空值和异常值后再转换与聚合。
- 查询失败、数据异常或口径未确认时，明确说明，不得编造答案。

## 七、AI 与业务逻辑分离

- 大模型负责意图理解、工具选择、参数组织和结果表达。
- Java 服务负责权限校验、参数验证、业务规则、数据访问和确定性计算。
- 金额汇总、计数、排序、占比等由 SQL 或 Java 完成，不让模型凭语言推理计算。
- 工具应有明确的输入、输出、错误语义和测试。
- 不要为首个 MVP 过早引入复杂的多 Agent 协作。

## 八、个人信息保护

CRM 表可能包含姓名、手机号、地址、生日和家庭成员等个人信息。

- 仅查询完成业务任务所必需的字段。
- 默认优先输出汇总数据，而不是个人明细。
- 不向模型传递不必要的个人身份信息。
- 日志不得记录不必要的个人信息、凭证或完整查询结果。
- 遵守公司关于测试数据、脱敏、访问审批和数据留存的规定。

## 九、开发流程

1. 先阅读代码和文档。
2. 明确需求、数据来源和业务口径。
3. 列出待确认问题和潜在风险。
4. 提出实现方案与涉及文件。
5. 经用户确认后再修改代码。
6. 编写或更新测试。
7. 使用测试数据库和脱敏样例验证。
8. 记录修改、测试结果、限制和后续事项。

用户明确要求“只分析”时，只进行阅读和分析，不修改文件、不执行数据库写操作。

## 十、交付要求

每次任务都要区分：
- 已从代码或文档确认的事实；
- 建议方案；
- 待业务确认的问题；
- 实际修改内容；
- 已实际执行的测试及结果；
- 尚未验证的事项和风险。

不得声称未执行的测试已通过，不得声称未验证的 SQL 已经准确。

## 十一、首阶段优先级

1. 检查 `SpringAi-MCP-RAG-Dev` 现有架构。
2. 明确 CRM 测试数据库连接方式与只读账号。
3. 与产品经理确认首批高频问题。
4. 确认核心指标口径。
5. 设计少量受控查询工具。
6. 用标准答案验证数据结果。
7. 再逐步完善自然语言交互、异常处理和审计能力。
