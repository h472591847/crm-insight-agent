# CRM 指标 - 数据来源 - 口径映射表（评审稿）

> 用途：把产品提出的老板看板指标逐条映射到现有 CRM 数据表（`expense_calendar_info` 订单头 / `expense_calendar_details` 消费明细 / `member_info` 会员），标明**计算逻辑、口径状态与数据缺口**，供产品经理逐条确认后再进入开发。
>
> 状态图例：
> - ✅ 可实现：数据来源明确、口径已确认。
> - 🟡 待确认口径：数据具备，但业务定义需产品确认后才能实现。
> - ❌ 数据缺口：现有三张表缺少必要字段/表，需补充数据来源或调整需求。
> - 🔒 涉及个人信息：输出到个人级，需先定脱敏与权限规则。
> - ⛔ 不实现：经产品确认从范围中移除。
>
> 本表不代表已获业务批准；🟡/❌/🔒 项在确认前不得用于正式统计。

## 一、全局已确认口径（作为计算基线）

| 约定 | 内容 |
|---|---|
| 有效订单条件 | `expense_state = '10' AND del_flag = '0'`（业务中不存在 `state='20'` 数据） |
| 消费金额字段 | 实付 `expense_realamt`（VARCHAR，需数值转换）；零售 `expense_stdtotal` 仅在明确要求时使用 |
| 退单表示 | 不使用状态位，原订单行 `expense_realamt` / 明细 `expense_d_realamt` 记为**负数**，`SUM` 时自然抵消 |
| 删除标记 | `del_flag`：`0`=正常，`1`=已删除 |
| 时间字段 | 消费类用 `expense_buyDate`（左闭右开区间）；会员新增用 `member_created` |
| 订单粒度 | `expense_calendar_info` 约定 1 单 1 行，订单数可用 `COUNT(*)` |
| 会员关联 | `member_mobile` 唯一；会员与消费通过 `mobile` 关联；查基表 `member_info` |
| 会员身份判定 | 标杆酒企**所有消费均计为会员消费**（2026-10-29）：活跃/消费类指标直接按订单表 `expense_mobile` 统计，不 JOIN `member_info` 验证身份；无“散客”概念 |
| 金额转换 | VARCHAR 金额统一用 `CAST(NULLIF(TRIM(x),'') AS DECIMAL(20,2))`；上线前需实测脏值 |
| 看板默认时间范围 | **近一年半**（2026-10-29 产品确认；取代 Phase 1 “当前自然月”旧口径，代码已同步：全局缺省 18 个月、上限 550 天） |
| 指标级时间上限 | 2026-10-30 新增 `maxRangeDays`：全局 550 天作缺省，指标可收紧。`PRODUCT_RANKING` 已声明 **92 天** + 默认 3 个月（旧 18 个月窗口实测 75.8s 超时） |
| 统计维度范围 | 2026-10-30 业务决策：**租户/商户（`member_tenant`/`expense_tenant`）不再作为筛选与统计维度**，只关注**门店**；传入 `TENANT` 会被服务端显式拒绝 |

## 二、数据缺口处置结论（产品已确认）

> 处置决策（2026-10-28 确认）：品牌、进销存/库存不做；毛利只有总额（订单级/汇总级），无明细级；品类/香型待只读核对数据取值。

| 编号 | 缺口 | 影响指标 | 处置结论 |
|---|---|---|---|
| G1 | 消费侧无品牌字段 | 偏好品牌、分品牌销售/排行 | **暂不做**：暂无品牌数据，相关指标移出范围（会员自填 `member_love_brand` 不代表实际购买，不采用）。 |
| G2 | 无明细级毛利 | 分品牌/品类/SKU 毛利排行 | **只保留总额/订单级毛利**：`gross_margin` 仅在订单头 `expense_calendar_info`（及会员 `gross_margin_year`）。商品级毛利排行移出范围；门店毛利（订单级汇总）可做。 |
| G3 | 无采购/库存表 | 头部名酒"进销存" | **不做进销存/库存**；"名酒销售"（按商品名）仍可做。 |
| G4 | 品类/香型字典未知 | 品类分布、分品类排行 | **待只读核对**：需在 Step 0 查看 `expense_d_commCodeName` 实际取值，确认能否映射"白酒/红酒/…""酱香/浓香/清香"，再决定品类排行是否纳入 Phase 2。 |
